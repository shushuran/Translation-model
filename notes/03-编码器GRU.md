## 1. 编码器在整体架构里的位置

```
src_ids (B, S) ──Embedding──▶ (B,S,D) ──逐时间步 GRU──▶ (B,S,H) ─┬─▶ H_seq   给注意力当 keys/values
                                                                  └─▶ h_final 给解码器当初始隐状态
```

编码器的任务是把变长的源句压成**一组定长的向量**。
注意它输出的是**整个序列**的隐状态 `H_seq`，而不是只有一个末状态 ——
这正是注意力能工作的前提：没有 `H_seq` 就没有东西可以"注意"。

## 2. Linear：`y = xW + b`

| | 公式 | 说明 |
|---|---|---|
| 前向 | `y = x @ W + b` | `W (in,out)`，`b (out,)` |
| `dW` | `xᵀ · dy` | 把 batch 维求和掉 |
| `db` | `Σ dy` | 对 batch 维求和 |
| `dx` | `dy · Wᵀ` | |

**支持任意前置维度**很重要：GRU 喂 `(B, in)` 的向量，注意力喂 `(B, T, in)` 的张量。
内部统一展平成 `(B·T, in)` 做一次矩阵乘法，比写两套分支干净得多。

## 3. Embedding：花式索引是**拷贝**语义

```python
grad[idx] += dout          # 错！重复索引会丢梯度
np.add.at(grad, idx, dout)  # 对
```

`grad[idx] += dout` 展开后是：

```python
tmp = grad[idx]        # 先把 idx 对应的行**复制**出来（花式索引返回拷贝，不是视图）
tmp = tmp + dout
grad[idx] = tmp        # 再整体写回 —— 后面的覆盖前面的
```

实测（`idx = [1, 1, 1]`，`dout` 全 1）：

| id | `np.add.at`（正确） | `grad[idx] +=`（错误） |
|---|---|---|
| 1 | `[3, 3]` | `[1, 1]` |

**这个坑在本任务里一定会踩到**：源句「2008年11月11日」的 token 是

```
['2','0','0','8','年','1','1','月','1','1','日']
重复 token：{'0': 2, '1': 4}
```

`'1'` 一句话里出现 **4 次**。用错写法，这些高频数字的 embedding 永远学不动 ——
而每个日期里数字都会重复，等于模型最重要的那部分参数全废了。

## 4. GRU 公式：本项目采用 PyTorch 约定

```
r = σ(x·W_ir + b_ir + h·W_hr + b_hr)            # 重置门 reset
z = σ(x·W_iz + b_iz + h·W_hz + b_hz)            # 更新门 update
n = tanh(x·W_in + b_in + r ⊙ (h·W_hn + b_hn))   # 候选状态 new
h' = (1 - z) ⊙ n + z ⊙ h
```

### ⚠ 两个最常见的混淆点

**（1）`z` 的含义与原论文相反**

| 出处 | 混公式 | `z` 的语义 |
|---|---|---|
| PyTorch / 本项目 | `h' = (1-z)⊙n + z⊙h` | `z = 1` → **保留旧状态**（不更新）|
| Cho et al. 2014 | `h' = (1-z)⊙h + z⊙h~` | `z = 1` → **采纳新值** |

同一个符号 `z`，含义正好反了。**查资料时先看公式，不要只看符号名。**

**（2）`r` 的位置不同**

- PyTorch：`r ⊙ (h·W_hn + b_hn)` —— 先线性变换，再逐元素缩放
- 原论文：`U(r ⊙ h)` —— 先逐元素缩放，再线性变换

数学上**不等价**，实现时必须选一种。本项目跟 PyTorch。

### 门的语义（数值实验确认）

脚本第 [3] 节把偏置推到 ±30 来强制门饱和，实测：

| 实验 | 观测量 | 结果 |
|---|---|---|
| `z ≈ 1` | 输入从 `x1` 换成 `x2` | 差 `0.000e+00`（输出与输入**无关**）|
| `z ≈ 1` | 与 `h` 的差 | `0.000e+00`（`h' ≡ h`，记忆原样传递）|
| `z ≈ 0, r ≈ 0` | 历史从 `h1` 换成 `h2` | 差 `0.000e+00`（**完全忽略历史**）|

> `z` 控制「保留多少旧状态」——长期记忆的开关
> `r` 控制「算新候选时参考多少旧状态」——短期遗忘的开关

注意 `z ≈ 0` 但 `r` 正常时输出**仍受历史影响**（实测差 `9.5e-2`），
因为候选状态 `n` 里还有 `r ⊙ (h·W_hn)` 这一项。两个门是配合工作的，不是独立开关。

## 5. 工程实现：三个门拼成一个矩阵

朴素写法是 6 个独立线性层、6 次矩阵乘法。本项目拼成两个大矩阵：

```
W_ih : (in, 3H)     列顺序 [r | z | n]
W_hh : (H,  3H)
gates_x = x @ W_ih + b_ih     # (B, 3H)  —— 一次乘法得到三个门
gates_h = h @ W_hh + b_hh
```

然后切片。这不是"为了简洁牺牲效率"，而是**更快**：

```
单次前向（B=32, in=4, H=5）： 拼接 42.8 μs  vs  6 次小乘法 50.7 μs
```

PyTorch 内部就是这么存的（`weight_ih_l0` 形状是 `(3H, in)`）。
维度越大差距越明显，因为大矩阵乘法能吃满 BLAS。

**唯一要小心的是**：反向传播时切片后的梯度必须**按同样的顺序拼回去**，
拼错了形状照样对得上，但数值全错。脚本第 [4] 节用"6 个独立向量-矩阵乘法"
的朴素实现交叉验证了这一点。

## 6. GRU 单元的反向传播推导

从 `h_new` 往前推：

| 前向 | 反向 | 要点 |
|---|---|---|
| `h' = (1-z)⊙n + z⊙h` | `dn = dh' ⊙ (1-z)`<br>`dz = dh' ⊙ (h - n)`<br>`dh(直接) = dh' ⊙ z` | `∂/∂z` 是 `(h-n)`，**不是** `h` |
| `n = tanh(gx_n + r⊙gh_n)` | `dpre_n = dn ⊙ (1-n²)`<br>`dr = dpre_n ⊙ gh_n`<br>`dgh_n = dpre_n ⊙ r` | tanh 导数用前向缓存的 `n` |
| `r = σ(gx_r + gh_r)` | `dpre_r = dr ⊙ r ⊙ (1-r)` | sigmoid 导数 `σ(1-σ)` |
| `z = σ(gx_z + gh_z)` | `dpre_z = dz ⊙ z ⊙ (1-z)` | |
| `gates_x = x@W_ih + b_ih` | 把 `[dpre_r \| dpre_z \| dpre_n]` 拼回 `(B,3H)` | **顺序必须与 forward 一致** |
| `gates_h = h@W_hh + b_hh` | 拼 `[dpre_r \| dpre_z \| dgh_n]` | 注意 `n` 用的是 `dgh_n` 不是 `dpre_n` |
| 两个投影 | `dW = xᵀ·d_gates`，`db = Σ d_gates`，`dx = d_gates @ Wᵀ` | |
| 汇合 | `dh_prev = d_gates_h @ W_hhᵀ + dh(直接)` | **两条路要相加** |

实测梯度检验最大相对误差 **3.94e-09**。

## 7. BPTT 的三个坑（第三个真的踩了）

### 坑 ① 参数梯度必须累加

同一个 cell 在前向循环里被调用 S 次。所以 `cell.zero_grad()` 只能在循环**外面**调用一次，
循环里每次 `cell.backward()` 都是往上加。

**忘记了会怎样？** 实测对照（在循环里每步 zero_grad）：

| 参数 | 正确范数 | 错误范数 | 比值 |
|---|---|---|---|
| `cell.W_hh` | 0.00932 | **0.00000** | **0.000** |
| `cell.W_ih` | 0.38153 | 0.26694 | 0.700 |
| `cell.b_ih` | 8.71945 | 3.07302 | 0.352 |
| `emb.weight` | 0.43519 | 0.43519 | 1.000 |

`cell.W_hh`（隐状态→隐状态）的比值恰好是 **0.000**。原因：反向循环最后一次
`zero_grad` 在 `t=0`，而 `t=0` 时上一隐状态 `h₋₁ = 0`，`h @ W_hh` 恒为 0，
梯度自然也是 0。

> 后果不是"RNN 学得慢"，而是「**根本不是 RNN**」——
> 循环连接完全学不到东西，退化成只看当前输入的前馈网络。

这种错误不报错、不出 nan、loss 照常下降（只是下降得慢），
**梯度检验是唯一能提前发现它的手段。**

### 坑 ② 中间量必须逐步保存 ← 本项目真的踩到了

`Module._cache` **只有一个槽位**，每次 `forward` 都覆盖它。
对前馈层没问题（前向一次、反向一次）。但循环网络前向循环调用 cell S 次后，
`_cache` 里只剩**最后一次**的中间量。反向传播时每个时间步都在用第 S-1 步的数据算梯度。

这个 bug 的实测表现：

```
正确实现     最大相对误差  3.75e-07   ✓
不恢复中间量  最大相对误差  1.00e+00   ✗     相差 5 个数量级以上
```

**它有多隐蔽**：形状全对得上、不报错、不出 nan。而且——
**GRU 单元的独立梯度检验是通过的**（3.94e-09），因为单步调用时 `_cache` 就是对的。
只有**编码器端到端**的检验才暴露出来。

修复：给 `Module` 加 `save_cache()` / `load_cache()`，
前向循环里 `caches.append(cell.save_cache())`，反向循环里
`cell.load_cache(caches[t])` 再 backward。

> 这就是"用时间换空间"的经典取舍，也是 PyTorch autograd 保存
> `saved_tensors` 做的事。**先验证零件、再验证整体**的流程在这里救了命。

### 坑 ③ 冻结状态的反向有两条路

前向是 `h_t = valid·h_new + (1-valid)·h_{t-1}`，反向自然分两路：

```
valid·dh_t        -> 走 cell 内部，绕一圈回到 h_{t-1}
(1-valid)·dh_t    -> 直接回到 h_{t-1}（跳过 cell）
```

漏掉第二条会在 padding 位置丢梯度。测试里专门往 padding 位置灌了巨大的假梯度，
确认它确实沿直接路径回传了（不是被静默丢弃）。

## 8. padding 为什么必须让状态「冻结」

朴素做法：直接在补齐序列上把 GRU 跑完。因为本项目是**右填充**，
padding 都在句尾，看起来"不影响前面的输出"。但有两个致命问题：

1. **`h_final` 被污染。** 句尾多跑几步 `<pad>` 后，最终隐状态已经偏离
   "读完最后一个真词"的状态。而 `h_final` 正是解码器的初始隐状态。
2. **结果随 batch 组成漂移。** 同一个句子在不同 batch 里 padding 个数不同，
   会得到**不一样**的 `h_final` → 同一份输入时而翻译对、时而翻译错，且不可复现。

解决办法：

```
h_t = valid_t ⊙ GRU(x_t, h_{t-1}) + (1 - valid_t) ⊙ h_{t-1}
```

实测（同一句「3 4 5」，加不同数量的 `<pad>` 后 `h_final` 的变化）：

| 填充数 | 冻结状态 | 不冻结（朴素） |
|---|---|---|
| 0 | `0.000e+00` | `0.000e+00` |
| 1 | `0.000e+00` | `9.349e-03` |
| 4 | `0.000e+00` | `1.745e-02` |
| 8 | `0.000e+00` | `1.852e-02` |

冻结之后，`H_seq` 的真实位置和 `h_final` 都**逐位不变**。

> 注意一个容易想歪的地方：**前向**方向 padding 不影响真实位置，
> 但**反向**方向，如果有人在 padding 位置的输出上放了梯度，
> 它会沿冻结路径原样回传到上一步。这是正确的（前向是恒等拷贝，反向就是恒等拷贝），
> 不是 bug。测试里专门验证了这一点。

## 10. 本步踩坑记录

| # | 坑 | 怎么发现的 | 教训 |
|---|---|---|---|
| 1 | `cell._cache` 单槽位被循环覆盖，BPTT 每步用错中间量 | **编码器端到端**梯度检验报 1.00e+00 | 零件对了不代表整体对了；循环网络必须 `save_cache`/`load_cache` |

| 3 | 测试里设置完权重表忘记先 `forward` 就 `backward` | `RuntimeError` | 这个报错设计得值 —— 静默用空 cache 算梯度才是最糟的 |

## 下一步预告

第 4 步把第 2、3 步的零件拼成**带注意力的解码器**：

```
h_final ──▶ 解码器初始隐状态
H_seq   ──▶ 注意力的 keys / values

for t in 0..T-1:
    context, weights = attention(query=解码器隐状态, keys=H_seq, values=H_seq, mask=src_mask)
    y_t = Decoder(x=tgt_in[t], h_prev, context)     ← 新的 GRU 单元，输入拼接 context
    loss += CrossEntropy(y_t, tgt_out[t])
```

需要新处理的两件事：

1. **反向传播要穿过注意力层**：`dcontext` 一路回到解码器，`dkeys/dvalues` 一路回到编码器
   （`dvalues = dkeys`，两者相加后传给编码器）。这就是第 2 步 `attention.backward`
   返回三个输入梯度的原因。
2. **解码器也要逐步缓存**（坑 ② 的教训）。

注意力（第 2 步）和编码器（第 3 步）都已经是被验证过的零件了，
第 4 步出问题时可以直接排除它们。
