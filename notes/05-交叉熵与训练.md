## 0. 最重要的一件事：我们的数据划分是错的

第 5 步最大的收获不是"训练跑通了"，而是**训练暴露了第 1 步数据设计的缺陷**。

第一次训练（400 步）的结果：

```
训练集：TF token 0.9977   整句 0.9778
测试集：TF token 0.8951   整句 0.0000     ← 一条都没对
```

输出的错误很有规律：

```
2035年06月03日   参考 3/June/2035      预测 3/June/2025
2036年5月3日     参考 3/May/2036       预测 3/May/2026
2039年2月18日    参考 18/February/2039 预测 18/February/2029
```

**模型从来没有输出过测试年份（2035~2039），只输出 2020/2025/2026/2027/2028/2029
—— 全部落在训练年份范围内。** 这是"背诵"的铁证。

两条原因：

1. **4000 条样本只覆盖 30 个年份 = 平均每个年份出现 133 次。**
   把 30 个年份背下来就足以在训练集上拿 97.8%，模型**根本没有动力**去学照抄数字。
2. **2000~2029 的年份第三位只能是 0/1/2**，测试年份的第三位是 3 ——
   这个「位置上的数字」训练时从未出现过。

### 修法

让划分同时满足两条硬性要求，并用测试把它们钉死：

| 要求 | 现在 | 修复前 |
|---|---|---|
| 每个数位上出现过的数字，训练集都覆盖 | ✓（千位 1~5、其余 0~9） | ✗（千位恒 "2"，百位恒 "0"） |
| 样本数 / 不同年份数 接近 1 | **1.47 次/年**（4000/2725） | **133 次/年**（4000/30） |
| 测试年份与训练不重叠 | ✓ | ✓ |

新的区间：`train=(1000,5799)` / `dev=(5800,5899)` / `test=(5900,5999)`。

### 效果（**同样只训练 400 步**）

| | 修复前 | 修复后 |
|---|---|---|
| 训练集整句准确率 | 97.78% | **100%** |
| 测试集整句准确率（自回归） | **0.00%** | **99.75%** |
| 生成的年份落在训练年份集合中 | ~100% | **0.00%** |
| 注意力归一化熵（越低越集中） | 0.51 | **0.34** |

> **这个教训比任何一行代码都值钱**：
> 一个"看起来在考泛化"的数据划分，完全可能因为区间太窄而变成一道背诵题。
> **必须用数据验证，而不是想当然。**
> 现在 `tests/test_data.py` 里有 9 项断言专门守这两条要求。

脚本里也加了自动化的**背诵检测**：统计模型生成的年份有多少落在训练年份集合里。

## 1. 交叉熵：反向只有一行

```
前向   loss = -(1/N) · Σ_{有效位置} log softmax(logits)[target]
反向   dlogits = ( softmax(logits) - onehot(target) ) / N
```

其中 `N` 是**有效位置数**（mask=1 的个数），不是 batch 总元素数 ——
这样不同 batch 里 padding 比例不同时，loss 量级和梯度尺度才稳定。

**为什么反向这么简洁？** 设 `p = softmax(z)`，`L = -log p_y`：

```
∂L/∂z_j = -(1/p_y) · ∂p_y/∂z_j
        = -(1/p_y) · p_y(δ_yj - p_j)
        = p_j - δ_yj
```

`softmax` 的 Jacobian 和 `log` 的导数**互相抵消**了。这就是框架都提供融合
`cross_entropy` 算子的原因：把 softmax 和 log 合起来算，省一次矩阵运算，
更重要的是**避免数值下溢**。

### 必须用 `log_softmax`，不能用 `log(softmax(...))`

```
log_softmax(x) = x - max(x) - log Σ exp(x - max(x))
```

实测（`x = [1000, 0, -1000]`）：

```
log_softmax      -> [0, -1000, -2000]            ✓ 有限
log(softmax(x))  -> [0, -inf, -inf]              ✗ 下溢成 -inf
```

`softmax` 会先把很小的概率压成 0，再取 log 就得到 `-inf`，梯度直接坏掉。
`log_softmax` 把"减最大值"和"取对数"合并进同一个表达式，全程不需要真的算出那个小概率。

### padding mask

`<pad>` 位置的目标 id 是 0，如果不加 mask，模型会花大量精力去预测 padding，
而且 padding 比例一变，loss 量级就漂移。实测 mask 前后：

```
不加 mask  loss = 1.9835
加 mask    loss = 1.9411
```

**整批被 mask 掉时的行为也必须定义好**（除以 0 会出 nan）：

```
mask 全 0  ->  loss = 0，梯度全为 0，无 nan     ✓
```

## 2. Adam

```
m_t = β₁m_{t-1} + (1-β₁)g_t              一阶矩
v_t = β₂v_{t-1} + (1-β₂)g_t²             二阶矩
m̂_t = m_t/(1-β₁ᵗ),  v̂_t = v_t/(1-β₂ᵗ)    偏差修正
θ_t = θ_{t-1} - lr · m̂_t/(√v̂_t + ε)
```

### 偏差修正到底修什么

`m` 和 `v` 都初始化为 0，前几步严重偏小。实测单步情况（`lr=1, g=5`）：

```
有偏差修正    首步更新量 = 1.000·lr      ← 恰好是 lr
无偏差修正    首步更新量 = 3.162·lr      ← 偏**大** 3.16 倍
```

推导：单步时 `m/√v = (1-β₁)g / (√(1-β₂)|g|) = 0.1/√0.001 = 3.162`。

> 注意方向：偏差修正是把**偏大**的首步压回正常，不是把偏小拉上来。
> （我一开始把这个方向写反了 —— 实验结果纠正了它。）

### 为什么 Adam 正好适合本项目

第 4 步测出 `attn.W_q` 的梯度比其他参数小 **7 个数量级**（`5.9e-9` vs `0.1`）。
更新量是 `m̂/(√v̂ + ε)`，分子分母都正比于梯度的尺度，**尺度因子互相抵消**。
所以即使用朴素 SGD + 统一学习率几乎不会更新那个参数，Adam 依然能给它合理的步长。

实测的梯度范数分布（训练全程）：

```
min 0.000   median 0.001   max 1.443      clip 阈值 5.0
被裁剪的 step 数：0 / 3000
```

一次都没触发裁剪 —— 序列只有 10 步，BPTT 不会爆炸。

## 3. 全局范数梯度裁剪

```
g ← g · min(1, max_norm / (‖g‖₂ + ε))
```

**必须用全局范数，不能用逐张量裁剪。** 逐张量裁剪会改变各参数之间梯度的
**相对比例**；全局裁剪只是统一缩放，保持了梯度的方向。RNN 的梯度爆炸是
整体性的（BPTT 连乘），所以全局裁剪才对。

**范数要在裁剪之前记录**，否则你永远看不到爆炸。

实测的验证：

| 检查 | 结果 |
|---|---|
| 返回裁剪**前**的范数 | `5.298218` = 手算值 |
| 裁剪后总范数 = max_norm | `0.99999981` |
| 各元素按同一比例缩放（方向不变） | 比值的 std `8.0e-18` |

## 4. warmup + 余弦退火

```
warmup 段：  lr = base_lr · (step+1) / warmup_steps
余弦段：     lr = base_lr · ( 0.1 + 0.9·(1+cos(π·p))/2 )
```

**为什么要 warmup？** 训练最初几步参数还是随机的，梯度方向噪声很大；
直接上大学习率容易把参数推到坏区域。先小步走一段，等方向稳定了再加速。
实测首步 `lr = 6.67e-06`（base 的 1/300），第 300 步达到峰值 `2.0e-03`。

**为什么要退火？** 后期学习率小，参数才能在最小值附近稳定下来。
如果一直保持大学习率，loss 会在最优点附近持续抖动。

实测曲线：`6.67e-06 → 2.0e-03（峰值）→ 2.0e-04（末步）`。

## 5. 训练循环的顺序

```python
for step in range(max_steps):
    lr = warmup_cosine_lr(step, max_steps, base_lr)
    opt.set_lr(lr)

    batch = next(stream)
    opt.zero_grad()                              # ① 必须先清零
    loss, _, _ = model.forward(batch)            # ② 前向
    model.backward()                             # ③ 反向（只累加）
    grad_norm = clip_grad_global_norm(...)       # ④ 先记录，再裁剪
    opt.step()                                   # ⑤ 更新
```

顺序错了会出各种隐蔽问题：

* 忘了 ① → 梯度跨 step 累积，等价于用了巨大的 batch，训练行为完全不同
* ③ 和 ⑤ 之间插了别的前向 → cache 被覆盖（第 3、4 步的坑）
* ④ 放在裁剪之后 → 梯度范数永远是 `≤ clip`，看不到爆炸

**批次流用 `drop_last=True`**：最后一个不完整批次样本少，平均梯度噪声更大；
固定大小能让 loss 曲线更平滑。

## 6. 健全性检查：先过拟合 10 条样本

**这是最省时间的排错手段。** 如果模型连 10 条样本都记不住，那一定是代码有 bug，
而不是"模型太小""数据太难"—— 这时候调超参数纯属浪费时间。

它同时验证三件独立的事：

1. 前向能产生有区分度的输出
2. 反向能把梯度正确传回**每一个**参数
3. 优化器真的在更新参数

实测：

```
step    0   loss 3.2954   token_acc 0.0538
step   50   loss 1.2893   token_acc 0.6344
step  100   loss 0.0745   token_acc 1.0000
step  399   loss 0.0012   token_acc 1.0000

teacher forcing：token 1.0000  整句 1.0000
自回归贪心    ：token 1.0000  整句 1.0000      ← 连 <eos> 都学会了
```

12.6 秒就能得到"整条链路是通的"这个结论。

## 8. 一个诚实的观察：任务现在有点太简单了

修好数据划分之后，模型在第 ~700 步就达到 100%，之后 2300 步都在原地。
这有两个后果：

1. **exposure bias 变成了 0**，这个本来很有教育意义的对比没有体现出来。
   原因很直接：模型在测试集上从不出错，就没有"错误累积"的机会。
2. **第 6 步的 Beam Search 在 100% 上没有提升空间**（贪心已经是最优）。

所以第 6 步打算这样处理：

* Beam Search 照常实现并**充分测试**（它本身就是经典算法，值得写对）；
* 用**训练不足的中间 checkpoint**（比如 300 步的）来对比贪心 vs Beam，
  那时才能看出 Beam 的优势；
* 另外准备把数据难度调高（打开 `include_weekday`，目标变成
  `5/March/2024/Tuesday`，序列更长、映射更复杂），在更难的设置上做对比。

## 9. 本步踩坑记录

| # | 坑 | 怎么发现的 | 教训 |
|---|---|---|---|
| 1 | 数据划分太窄，模型靠背诵过关 | 训练后测试集整句准确率 0%，且生成的年份**从不超出**训练年份集合 | **"看起来在考泛化"的划分可能变成背诵题，必须用数据验证** |
| 2 | 以为"没有偏差修正时首步更新量偏小" | 测试失败，实测是 `3.162×lr`（偏**大**） | 偏差修正的方向容易记反，推导一遍 |
| 3 | 用"均匀 logits 时准确率 = 1/V"做断言 | 测试失败：`argmax` 在并列时全返回 0 | 并列情况的 tie-breaking 会破坏统计性断言 |
| 4 | 用"参数清零后 loss 改变 > 1e-3"做断言 | 随机初始化本来就接近均匀分布，差只有 2e-4 | 断言要选**强等价性**（清零后 loss 恰为 `log V`），而不是弱不等式 |

## 下一步预告

第 6 步实现 **Beam Search**：

```
贪心：每步只保留 1 条最优前缀
Beam：每步保留 beam_size 条最优前缀，最后按「长度归一化的对数概率」选一条
```

要讲的点：

1. **为什么用对数概率之和**（乘积会下溢成 0）
2. **长度惩罚**：纯对数概率偏好短句（每多一个词就多一个负项），
   所以常用 `score / ((5+len)/6)^α`
3. **什么时候 Beam 有用、什么时候没用**：贪心已经 100% 时它不可能更好；
   在训练不足或有局部最优陷阱时才有收益
4. **算力换精度**：Beam 的代价是 `beam_size` 倍的解码开销
