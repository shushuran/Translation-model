# 第 8 步学习笔记 · 消融实验：注意力到底带来了多少

> 对应代码：`seq2seq_attn/attention.py`（新增 `MeanContextAttention`）、`scripts/08_ablation.py`
> 断言测试：`python tests/test_ablation.py`（54 项）

这一步要回答的问题很直接：**如果不加注意力会怎样？其他设计选择各值多少？**

---

## 1. 为什么要先加一个「无注意力」基线

`attn_type` 原先只有 `bahdanau` / `dot` 两种，它们都是**注意力**。
要量化注意力的贡献，必须能把注意力**真正拿掉** —— 于是新增：

```python
class MeanContextAttention(Module):
    """context 恒等于 values 的掩码加权平均（与 query 无关，所有解码步相同）"""

    def forward(self, query, keys, values, mask=None):
        w = mask / mask.sum(-1, keepdim=True)          # (B, S)
        weights = broadcast(w[:, None, :], (B, Tq, S))
        return weights @ values, weights
```

这就是 Bahdanau 2015 提出注意力**之前**的标准做法：
把整句压成一个**固定长度**的 context 向量，解码每一步都用同一个。
等价于「注意力权重恒为均匀分布」。

它零参数、前向反向都极简，但**完整保留了 `forward` 的签名和返回值** ——
这样消融实验里唯一的变量就是"用不用注意力"，其他代码一行都不用改。

## 2. 实验设置

| 项 | 值 |

| 训练步数 | 每个配置 1500 步（全模型约 600~750 步就到上限，留足余量） |
| 训练集 | **500 条（数据受限）** 和 **4000 条（数据充足）** 两套 |
| 开发/测试集 | 400 / 400 条，测试年份训练时从未出现 |
| 每项改动 | **单变量**（由测试断言保证） |

为什么要两套数据设置：完整数据下全模型 700 步就 100%，
很多消融项也会是 100%，表格里全是 `1.0000`，消融"消"不出信息。
压到 500 条后进入**数据受限**区间，各配置的差距才显现。

## 4. 五个结论

### ① 注意力是**必需的**，而且它把上限抬得很高

```
数据受限 500 条：99.50%  →  14.25%   （-85.25 个百分点）
数据充足 4000 条：100.0%  →  59.75%   （-40.25 个百分点）
```

去掉注意力后，context 是一个**固定的均值向量**，解码器只能靠
`h_final` 那 128 维去记住整句。数据翻 8 倍能把它从 14% 拉到 60%，
但**仍然远低于 100%** —— 说明瓶颈是**结构**（信息必须挤进定长向量），
不是数据量。这正是注意力被发明出来的原因。

### ②「注意力」这个机制比「注意力怎么算」重要得多

`dot`（缩放点积，**零参数**）在 500 条数据上拿到 **100%**，
而且收敛比 baseline 快 1.67 倍（450 vs 750 步）。

> **参数量不是关键，机制才是。** 33,024 个注意力参数换来的不是效果提升，
> 反而略慢一点。这也解释了为什么 Transformer 敢用零参数的点积注意力 ——
> 表达力靠**多头**和**维度**补，而不是靠打分函数的复杂度。

（这里点积甚至更好，一个合理的解释是：本任务的核心是"照抄数字"，
也就是**查询向量与被查向量的相似度匹配**，点积天然表达这件事；
加性注意力多出来的 `tanh` 非线性在这个任务上没有被用上。）

### ③ context 直接参与输出层很重要，但数据能部分补偿

```
output_s（输出层只吃 s_t）：
    500 条： 99.50% → 58.50%   （-41.00）
    4000 条：100.0% → 93.25%   （-6.75）
```

`output_mode="s"` 时 context 只能经 GRU 输入间接影响输出。
数据少时掉 41 个百分点，数据多时只掉 6.75 个 ——
**"少了这条信息通路"和"学不会"是两回事**：数据够多时 GRU 能学会把
context 的信息传递到隐状态里，只是效率低。

### ④ 桥接投影（`s₀ = tanh(W·h_final)`）**完全冗余**

`init_zero`（解码器初始状态恒为 0）在两套数据下都是 **100%**，
而且收敛最快（300 / 450 步）。

合理：注意力每一步都能直接取到编码器的全部输出，
所以"起点是什么"并不重要 —— 编码器的信息不需要靠初始状态传递。

> 这是一个**有用的负面结论**：一个看起来"设计得很讲究"的可学投影，
> 在这个架构下其实是多余的。不做消融就永远不会知道。

### ⑤ 对齐质量与最终效果强相关

| 配置 | 对齐命中率 | test AR 整句 |
|---|---|---|
| init_zero | 1.0000 | 1.0000 |
| dot | 0.9724 / 0.9806 | 1.0000 |
| baseline | 0.9128 / 1.0000 | 0.9950 / 1.0000 |
| output_s_emb | 0.9009 / 1.0000 | 0.9850 / 1.0000 |
| output_s | 0.5939 / 0.6256 | 0.5850 / 0.9325 |
| no_attention | 0.5961 / 0.5979 | 0.1425 / 0.5975 |

`no_attention` 的命中率 0.596 不是"随机"—— 它的权重恒为均匀，
所以 `argmax` 永远是位置 0，而位置 0 在"年份"的理想集合里、不在"日/月"里，
7 个位置里占 4 个 → 4/7 ≈ 0.57。**它压根没有对齐，只是恰好碰上了。**

这也说明：**看单一指标会被误导**。第 7 步的多个指标
（命中率 + 严格位置 + 单调性 + 熵）合起来看才可靠。

## 5. 一个必须讲清楚的边界

消融实验只能证明**相关性 + 结构必要性**，不能直接证明"模型是靠看了那里才答对的"。
真正严谨的因果证据需要**干预实验**（比如把某个位置的注意力强制置零，看输出怎么变）。

本项目做到的是：
1. 有明确的无注意力基线（结构上确实去掉了这条通路）
2. 有对齐质量的直接测量（第 7 步，100% 命中率）
3. 两者一起看，结论是稳的

但如果要写论文，还得补一句「注意力可解释性仍有争议」。

## 6. 本步踩坑记录

| # | 坑 | 怎么发现的 | 教训 |
|---|---|---|---|
| 1 | 用**未 mask 的人造损失** `(logits*G).sum()` 做梯度检验，`Embedding(padding_idx=0)` 把 `<pad>` 行梯度强制置零，两者对不上 | 梯度检验报 `dec.emb.weight` 解析=0 数值=0.1，其余张量全对 | **梯度检验要用真实的训练损失**；`padding_idx` 的正确性依赖"损失已经 mask 掉 pad"这个前提 |
| 2 | 梯度检验判据在 `spread=0 且 \\|解析梯度\\|≈0` 的元素上容差塌缩到 `1e-300`，任何舍入差异都判 FAIL | 加了噪声地板绝对项后通过 | 容差必须有**绝对下限**，否则"信号为 0"的元素会变成假阳性来源 |
| 3 | 测试里把维度变量 `d` 和梯度字典 `d` 重名 | `TypeError: int() argument must be... not 'dict'` | 短变量名在长函数里容易撞车 |

## 7. 八步回顾

| 步骤 | 一句话 | 关键产物 |
|---|---|---|
| 1 | 数据管道 | 逐位分词 + 防止背诵的年份划分 |
| 2 | 注意力机制 | 加性/点积前向反向 + 自校准梯度检验 |
| 3 | 编码器 GRU | PyTorch 约定的 GRU + BPTT |
| 4 | 解码器 | 三处汇合点的梯度相加 + 因果性验证 |
| 5 | 训练 | 交叉熵 + Adam + warmup/余弦，测试集 100% |
| 6 | Beam Search | 与暴力枚举逐位对照 + 提前停止 bug |
| 7 | 对齐可视化 | 命中率 100% + 「只有 10 月看定界符」 |
| 8 | 消融 | **去掉注意力从 99.5% 掉到 14.25%** |

整个项目的核心方法可以总结成一句话：

> **每个模块先独立验证再用；每个结论都用实验而不是推理来确认。**
>
> 八步里被实测纠正的错误有：数据划分让模型能靠背诵过关、
> 广播从右对齐导致的静默错位、BPTT 忘保存中间量、
> Beam Search 提前停止丢解、理想对齐漏写定界符、
> `padding_idx` 与未 mask 损失的冲突……
> 每一个都"看起来不像 bug"。
